<p style="margin: 0 0 10pt; line-height: 150%; font-size: 12pt;">The questions below are organized in a logical order - starting from the basics of EPM, moving through when and how to raise a request, and ending with special cases. Read them in sequence if you are new to EPM.</p>
<h3 id="_Toc239952696" style="margin: 18pt 0 8pt; line-height: 130%; font-size: 14pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; border-left: 4px solid #0F4761; padding-left: 10px;"><a name="_Toc239952696"></a>Understanding EPM</h3>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q1. What is CyberArk Endpoint Privilege Manager (EPM)?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">CyberArk EPM is a security tool that controls which applications on your device are allowed to run with administrator (elevated) rights. Instead of giving users permanent, device-wide administrator access, EPM allows elevation only for specific, approved applications or for a limited time - reducing the risk of malware, unauthorized software, or accidental system changes.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q2. Why has local admin access been removed for users?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Standing (permanent) local administrator access on a device is a significant security risk - if the device or account is compromised, the attacker also gets full administrator control. To reduce this risk, organizations remove permanent local admin rights and instead give users <strong>standard user rights</strong> by default. When elevated rights are genuinely needed, users can request them through EPM, either temporarily (JIT) or through an approved policy for a specific application.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q3. What is an EPM policy, and why is an application blocked even though I need it for work?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">An EPM policy is a rule configured in CyberArk EPM that allows a specific, named application to run with elevated rights automatically, without the user needing admin access to the whole device. If an application needs elevated rights to run, and no EPM policy currently covers it, application will not run properly - this is expected, normal behavior, not a fault with the application. The fix is to raise a EPM Policy Creation/Modification request so that application is specifically allowed to run with elevation for the intended users.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q4. What is Temporary Administrator Access (JIT)?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">JIT (Just-In-Time) Access gives user full, device-wide administrator rights for a short, defined period (default 3 hours) to complete a specific, approved task. Once the time ends, the elevated access is automatically removed, and the device returns to standard user rights.</p>
</div>

<h4 style="margin: 0 0 10pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q5. <div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q6. In which case should I raise a JIT request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Raise a JIT request when you need short-term, device-wide administrator access to complete a specific, approved activity - for example, installing a one-off tool, troubleshooting a device issue, or performing a task that does not repeat regularly and does not justify a permanent policy. Use JIT only when the need is temporary and clearly time-bound.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q7. In which case should I raise a Policy Creation/Modification request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Raise a Policy request when a specific application consistently needs elevated rights to install, update, or run for you or your team on an ongoing basis. Instead of repeatedly requesting temporary access, a policy permanently allows that one application to run elevated for the approved users, without granting broader device-wide admin rights. Also raise a Policy Modification request if an existing policy needs a change, such as a new application version, an updated file path, or an updated user group.</p>
</div>

<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q15. How long does it take to process a JIT request or a Policy request?</h4>
<p style="margin: 0 0 8pt; line-height: 150%; font-size: 12pt;">A JIT (Temporary Administrator Access) request is processed within 4 hours of receipt after manager approval.</p>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">A Policy Creation/Modification request is processed within 3 business days, provided all required information is included.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q16. What can cause delays in processing of Policy Requests?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Processing may be delayed if additional information or clarification is required, if there is a delay in the requestor's responses, or if further analysis, validation, or review is needed before implementation. Providing complete and accurate details up front, in Business Justification, Description, and Describe the Issue, helps avoid these delays.</p>
</div>
<h3 id="_Toc239952701" style="margin: 18pt 0 8pt; line-height: 130%; font-size: 14pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; border-left: 4px solid #0F4761; padding-left: 10px;"><a name="_Toc239952701"></a>Requests for Teams and Groups</h3>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q17. Can one request cover a whole team, or does every member need to raise a separate request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">One request is enough for a whole team. If 20 members of a team all need the same policy for application elevation, they do not need to raise 20 separate requests. A single Policy Creation/Modification request can be raised for the group, referencing the relevant Active Directory (AD) group instead of listing individual users.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q18. How do I specify a group of users in my request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">In the Description field, provide the name of the existing AD group that should receive the policy, along with the application details. Using an AD group, instead of listing individual usernames, allows the EPM Team to apply the policy to all current members at once, and it continues to apply correctly if group membership changes later.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q19. What if my team does not have an existing AD group?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">If a suitable AD group does not exist, reach out to the UAM team through the <a style="color: #0f4761;" href="https://olympusprod.service-now.com/quest?id=olympus_sc_cat_item&amp;sys_id=b5b57b6ddbbbc4503fefd7b7f49619f2" rel="nofollow">catalog link</a> to get a new AD group created first. Once the group is created, reference it in your EPM Policy Creation/Modification request.</p>
</div>
<h3 id="_Toc239952702" style="margin: 18pt 0 8pt; line-height: 130%; font-size: 14pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; border-left: 4px solid #0F4761; padding-left: 10px;"><a name="_Toc239952702"></a>Changes After Approval</h3>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q20. What happens if the application details or the list of users change after discussion with the EPM Team, or after approval?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">The EPM Team creates and applies the policy strictly based on what was reviewed and approved. If the application details (name, version, publisher, and so on) or the affected users/group change after submission or during discussion, this is treated as a modified request and requires fresh manager approval for the updated details before the EPM Team can proceed.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q21. Can I request additional changes after my policy has already been approved and created?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">If you need changes beyond what was already approved and fulfilled, raise a new Policy Creation/Modification request describing the additional changes. Do not expect additional or unapproved changes to be added under the original request.</p>
</div>
<h3 id="_Toc239952703" style="margin: 18pt 0 8pt; line-height: 130%; font-size: 14pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; border-left: 4px solid #0F4761; padding-left: 10px;"><a name="_Toc239952703"></a>Preparing Your Request</h3>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q22. Is there a form or template to help me prepare the details before raising a request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Yes. Use the <a style="color: #0f4761;" href="https://olympusssaemea.sharepoint.com/:x:/s/GlobalIdentityAccessManagement/IQBc2-x0NBy0QZ3j8m9hnRrjAR7dAXVoq16SLTOD7tsribw?e=9NUZZm" rel="nofollow">Requirement Gathering Form</a> to collect all necessary details, including application name, version, executable/file path, publisher, whether it is a new policy or a modification, and the affected user group or AD group. Completing this form before you raise the request helps avoid delays caused by missing information during review.</p>
</div>
<h3 id="_Toc239952708" style="margin: 18pt 0 8pt; line-height: 130%; font-size: 14pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; border-left: 4px solid #0F4761; padding-left: 10px;"><a name="_Toc239952708"></a>General Queries, Issues, and Exception Requests</h3>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q23. What is the difference between a General Query, an Issue, and an Exception Request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">A General Query is a question that does not fit the JIT or Policy categories (for example, clarifying how EPM works). An Issue is a problem with EPM itself or with a previously fulfilled request (for example, a policy was created but the application still does not run, or JIT access did not work as expected). An Exception Request asks for a deviation from the standard process - for example, JIT access for longer than 3 hours, or expedited processing for a business-critical situation. All three use the same catalog item and service option, they are differentiated by what you describe in Business Justification and Description, and by the Describe the Issue text.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q24. When should I raise a General Query/Exception request instead of a JIT or Policy request?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Use this category when your situation does not match either of the two standard request types, or when you need to report a problem with a request that was already approved and fulfilled. If your need still fits cleanly into JIT (temporary device-wide access) or Policy (ongoing elevation for one application), raise that specific request type instead - it will be processed under its standard SLA.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q25. My EPM Policy was approved and created, but the application is still blocked. What should I do?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Raise a General Query/Issues request, referencing the original Policy request number, and describe exactly what is happening (error message, when it occurs, device name). This may be a configuration mismatch (for example, the file path or publisher details not matching the actual application) and will be reviewed by the CyberArk EPM Team as an issue, rather than requiring a brand-new policy request.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q26. Can I request JIT access for longer than the standard 3-hour maximum?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">Yes, but only as an exception. Raise a General Query/Exception request, explain why the standard 3-hour window is insufficient, and provide the business justification. Extended-duration JIT access is reviewed case-by-case and is not automatically approved the way a standard JIT request is.</p>
</div>
<div style="margin: 0 0 14pt; padding-bottom: 12pt; border-bottom: 1px solid #E5E7EB;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q27. Is there a fixed processing time (SLA) for General Query/Exception requests?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">No. Unlike JIT (4 hours) and Policy (3 business days), General Query and Exception requests do not have a fixed SLA because each case is reviewed individually. Processing time depends on the complexity of the issue and whether additional approvals are required.</p>
</div>
<div style="margin: 0; padding-bottom: 4pt;">
<h4 style="margin: 0 0 6pt; line-height: 130%; font-size: 12.5pt; font-family: Candara, Tahoma, Geneva, Verdana, sans-serif; color: #0f4761; font-weight: bold; background-color: #eaf2f8; padding: 8px 12px; border-radius: 4px; border-left: 4px solid #2E75B6;">Q28. Does an Exception Request need more than my manager's approval?</h4>
<p style="margin: 0; line-height: 150%; font-size: 12pt;">It can. Depending on the nature of the exception (for example, a scope or duration that significantly exceeds standard policy), the CyberArk EPM Team may require additional review or approval beyond the requester's manager before the exception can be granted.</p>
</div>
